# 小影全栈：学习目标与逐轮实践

制定日期：2026-11-02。

项目目录：`D:\Files\Java\code\笔试项目\小影全栈`。

本文服务于本次笔试开发，目标是把完成项目的过程转化为能够独立解释、修改和排查问题的实际能力。功能范围与验收依据仍以 [需求分析与实施方案](需求分析与实施方案.md) 为准，本文不增加产品功能。

当前状态：仅完成需求和学习计划，以下轮次均未执行；文中的实验、代码、测试和面试回答不代表已完成成果。

## 1. 最终学习目标

完成本项目后，争取能做到：

1. 独立讲清一次 HTTP 请求经过前端、Java 分层、MyBatis 和 MySQL 的完整路径。
2. 根据一个业务要求确定接口、数据表、校验位置、状态变化和异常反馈。
3. 解释本项目事务、后台线程、任务状态的边界，并指出方案的失效窗口。
4. 用日志、接口响应和数据库记录判断问题发生在哪一层，完成一次定位和修复。
5. 对照实验说明多任务隔离、失败中断、查询异常和刷新恢复如何成立。
6. 从一个可运行的交付版本出发，说明配置、构建、测试、容器、数据持久化及已知限制。
7. 面试回答能提供自己的操作与证据，明确哪些工作由 AI 生成、哪些由自己判断和验证。

本次学习优先围绕业务所需知识展开，不要求先学完全部 Java、Spring、数据库和前端课程。每轮遇到基础缺口时，用一个与当前业务直接相关的小例子补齐，再回到项目。

## 2. 每一轮怎样学习

### 统一流程

1. **明确目标**：阅读本轮对应需求，画出输入、处理、输出和可能失败的位置。
2. **先做预测**：在看完整实现前，用自己的话回答两三个关键问题，不确定处明确写出来。
3. **分小块实现**：AI 可以生成骨架和代码，每个小块围绕一个可验证行为，阅读规模控制在自己能讲清的范围内。
4. **顺着请求读代码**：从调用入口追到数据库或文件，再追到响应；解释每一层的输入、输出和职责。
5. **亲手修改**：自己完成至少一个小变更，先预测影响位置，再修改和验证。必要时让 AI 提示下一步。
6. **做故障实验**：先写预期，再制造受控异常，观察响应、日志、数据库和页面，比较预期与实际。
7. **口述复盘**：用两到三分钟解释本轮功能，再接受两个追问；把仍说不清的问题记在本文末尾。

### AI 与自己的分工

| 工作 | AI 可以承担 | 自己必须参与 |
| --- | --- | --- |
| 设计 | 提供方案、画链路、解释取舍 | 说清选择理由和关键边界 |
| 编码 | 生成骨架、实现小功能、建议重构 | 追踪关键路径、完成一个实际修改 |
| 测试 | 起草行为测试、辅助定位 | 预测结果、运行验证、阅读失败信息 |
| 排障 | 根据证据提出假设 | 提供完整现象、选择检查动作、验证假设 |
| 文档/面试 | 整理事实、模拟追问 | 确认真实完成程度，用自己的话回答 |

遇到报错时，先记录：做了什么、预期是什么、实际是什么、相关日志/响应、已有判断。请求 AI 分析时，优先让它提出定位步骤和依据，再查看修复代码。涉及凭据的日志和配置先脱敏。

### 掌握程度

- 0：还没有接触。
- 1：看解释能理解，自己讲不完整。
- 2：能够独立解释正常路径，并完成一个小修改。
- 3：能够解释故障路径，依据证据定位问题，并说明设计限制。

关键业务目标争取达到 2，异步任务、事务和异常处理争取达到 3。这个评分用于安排补习，不作为机械阻断开发的门槛；临近提交时优先完整交付，把未掌握项和未实现项分别记录。

## 4. 第1轮：工程启动与一条请求链路

### 学什么

- JDK、构建工具、Node.js、Docker 分别负责什么，开发环境与运行环境有何区别。
- Spring Boot 的启动入口、依赖与配置文件；Controller、Service、Mapper 的职责。
- HTTP 方法、路径、状态码、JSON；端口、地址与数据库连接配置。
- 日志如何对应到一次请求，异常信息从哪里读起。

### 怎么学与怎么做

1. 盘点本机工具与可用容器环境，记录实际版本；按总需求方案锁定兼容依赖。
2. 建立前后端骨架和 MySQL，先用最小接口验证 Java 可访问，再验证数据库连接。
3. 画出“浏览器/接口工具 → Java → 数据库 → 响应”链路；给项目中的实际文件标注职责。
4. 亲手改一个接口响应字段并验证，区分改了源代码、重启应用、重新构建镜像的影响。

### 故障实验

在演示环境中临时使用错误数据库连接配置，观察启动/调用现象和日志；恢复后再次验证。先判断失败位置，再对照实际结果，记录实际错误类型，不预设所有连接失败都会返回同一响应。

### 面试追问

- main 方法启动后，接口是怎样被访问到的？
- 为什么要分 Controller、Service、Mapper？什么逻辑放在哪一层？
- 连接数据库失败时，先查地址、账号、服务状态还是业务 SQL？依据是什么？

### 本轮产物与完成标准

保留环境版本、启动命令、一次接口响应和故障定位摘要。能够不看代码画出请求路径，并指出对应文件；骨架能启动、数据库实际连通。

## 5. 第2轮：模板接口、SQL 与页面契约

### 学什么

- 表、主键、外键关联、筛选、排序、索引的基本用途。
- MyBatis 的 Mapper、参数绑定、结果映射，以及 SQL 到 Java 对象的关系。
- 实体、请求参数和响应 DTO 为什么可能不同。
- Next.js App Router、页面参数、组件、请求状态的最小必要知识。

### 怎么学与怎么做

1. 从模板列表和详情的字段反推最小数据结构，准备分类和模板种子。
2. 先写并执行查询 SQL，再通过 Mapper 和 Service 暴露接口。
3. 用接口实际响应实现列表与详情，参考配图建立暗色卡片网格及工作台骨架。
4. 亲手增加一个可见字段或分类筛选条件，同时修改 SQL/映射、DTO 和页面，检查链路是否完整。

### 故障实验

查询不存在的模板、切换到无数据分类、制造接口请求失败，观察它们与正常加载是否使用不同反馈。快速切换分类，检查旧响应是否覆盖新选择。

### 面试追问

- 模板卡片的数据究竟从哪里来？某字段为空，怎么定位？
- 参数绑定与直接拼接用户输入有什么区别？
- 查不到模板和接口不可用应该如何区分？
- 索引应该围绕哪些实际查询设计？

### 本轮产物与完成标准

保存表结构、核心 SQL、列表/详情响应样例和链路图。前端真实展示 Java 从 MySQL 读取的数据，能够独立说明一个字段的完整流转。

## 6. 第3轮：身份与个人记录隔离

### 学什么

- 浏览器 Cookie、服务端会话和用户记录分别保存什么。
- 身份识别与资源访问权限的区别。
- 为什么个人记录必须由后端限制归属；刷新后身份如何保持。
- 匿名身份的恢复能力与丢失边界。

### 怎么学与怎么做

1. 画出匿名会话创建、设置 Cookie、后续带 Cookie 请求的过程。
2. 实现当前身份获取和服务端归属判断，明确会话与用户表关系。
3. 亲手为一个个人资源接口增加归属检查；任务尚未实现时，可先用最小测试资源验证。
4. 用普通窗口与无痕窗口分别建立 A、B，观察会话和数据归属。

### 故障实验

删除演示 Cookie、使用失效会话、让 B 请求 A 的资源，分别记录响应。用新身份重新进入时检查旧缓存是否残留；后续任务实现后补查历史与结果图片权限。

### 面试追问

- 前端请求体中的 userId 为什么不能直接当成可信身份？
- 隐藏前端入口和后端拒绝访问有什么区别？
- 匿名用户换浏览器后还能找回记录吗？本方案如何说明限制？

### 本轮产物与完成标准

保留会话流程图、A/B 测试记录和归属校验位置。能解释刷新恢复身份与跨浏览器找回身份的区别，不把演示身份方案说成完整账号系统。

## 7. 第4轮：真实上传与双端校验

### 学什么

- multipart 请求、文件内容、文件元数据、磁盘文件和数据库记录的关系。
- 浏览器预览地址与服务端可用文件地址的区别。
- 资源关闭、文件名/路径生成、校验与异常反馈。
- 图片槽位状态、替换时的旧响应、上传完成后提交素材 ID 的原因。

### 怎么学与怎么做

1. 画出“选图 → 前端检查/预览 → Java 接收/检查 → 保存文件与记录 → 返回素材 ID → 提交任务”的过程。
2. 实现每个槽位的选择、预览、替换、移除、上传中和失败状态。
3. 亲手修改一项模板素材限制，检查客户端和 Java 是否同时遵守。
4. 通过接口工具直接提交请求，验证页面校验不是唯一入口。

### 故障实验

上传超限文件、格式不符文件；提交数量错误、重复素材 ID 或他人素材；快速替换正在上传的图片，检查旧响应是否回填。讨论文件保存成功而记录保存失败时可能留下什么，以及本项目如何处理或声明限制。

### 面试追问

- 为什么只检查文件后缀不够？
- 数据库事务能否自动撤销已经写到磁盘的文件？
- 文件、记录、预览地址和任务输入之间怎么关联？
- 哪些错误应在受理前拒绝，哪些会成为后台阶段失败？

### 本轮产物与完成标准

保留素材字段说明、校验表和一次绕过前端的验证。文件真实存在且可供 Java 使用，替换/移除不串槽位，上传未完成不能提交。

## 8. 第5轮：三步骤异步成功链路

### 学什么

- 请求线程与后台线程的职责，异步与真正并行的区别。
- 整体状态、当前阶段、阶段记录和状态转换。
- 事务提交、后台派发、数据可见性、短事务与长耗时操作的边界。
- Spring 代理、事务/异步调用路径需要注意的位置。

### 怎么学与怎么做

1. 先画时序：校验 → 创建任务并提交 → 投递 Worker → 返回 ID；Worker 依次更新阶段与结果。注意返回响应与 Worker 推进可能交错。
2. 列出每一步读写的字段，明确哪些写入一起提交，哪些操作在事务外。
3. 实现正常路径：素材检查 → 模拟生成 → 结果整理，完成后提供真实可访问的预置结果图。
4. 亲手调整一个阶段耗时，验证接口受理不等待全流程，查询可看到中间状态。

### 故障实验

长耗时任务提交后关闭浏览器，再重新打开查询；核对相同任务 ID、数据库和 Java 日志。通过可控测试观察工作线程在任务提交前/后读库的差别，记录实际隔离配置与时序，避免凭一次运行推导所有事务环境。

### 面试追问

- 为什么要先创建记录，再派发后台任务？
- 为什么整个流程一个大事务可能影响阶段可观察性？
- 同一对象内部调用带注解方法，实际是否经过代理，怎么确认？
- 前端定时查询为什么不能承担阶段推进？

### 本轮产物与完成标准

保留状态图、事务/线程时序图、阶段日志和数据库快照。能解释一次成功任务的每次关键写入；提交返回、关闭页面后继续执行、中间状态和最终结果都有证据。

## 9. 第6轮：失败、排队与可靠性边界

### 学什么

- 异常捕获的位置、失败中断、错误码与用户文案。
- 线程数、队列、拒绝策略分别影响什么；资源有上限时如何受理。
- 数据库状态与内存队列之间的一致性窗口。
- 关闭浏览器、Java 重启和数据库重启的差异。

### 怎么学与怎么做

1. 实现指定阶段失败和每阶段延迟，配置随任务保存。
2. 使用单 Worker 观察多任务排队，说明排队不等于执行失败。
3. 在受控测试中设置小队列，触发拒绝并检查落库，避免任务永久停在等待。
4. 亲手增加/修改一个失败原因及其测试，确认它只影响指定任务。

### 故障实验

分别触发三阶段失败，核对后续阶段没有执行；队列满时检查提交线程有没有承担制作工作；重复查询终态，确认不会回退。重启 Java 后检查遗留任务，按实际实现解释未恢复执行或中断收尾行为。

### 面试追问

- 线程池满了怎么办？为什么本项目不适合把耗时工作退回请求线程？
- 数据库已经提交，但进程在派发前退出，会怎样？
- AFTER_COMMIT 监听器内还要写库，事务边界怎样确认？
- 本项目的幂等、重试、重启恢复分别做到了什么？哪些没做？

### 本轮产物与完成标准

保留三类失败证据、排队/拒绝记录和边界说明。能指出方案解决的问题及仍存在的窗口；没有验证过的恢复能力不写成已支持。

## 10. 第7轮：多任务、查询异常和刷新恢复

### 学什么

- 上传、提交请求、任务业务状态和查询状态为什么分开。
- 前端组件状态、查询缓存、数据库状态的职责。
- taskId/userId 隔离、轮询结束条件、取消请求、迟到响应和版本合并。
- 页面切换、身份变化、历史筛选和未完成任务恢复。

### 怎么学与怎么做

1. 完成左制作右历史工作台及全部历史入口，复用任务卡片与状态来源。
2. 画出 A/B 两个任务分别更新的过程，标记缓存键和终态停止条件。
3. 亲手实现或修改一次“恢复查询”，证明它只读取已有任务。
4. 为初始化、刷新、切换页面与身份失效列出清理/恢复动作。

### 故障实验

A成功/B失败交错返回；处理中阻断查询后恢复；全部任务结束观察网络；卸载页面和身份变化后让旧响应迟到；刷新恢复未完成任务。检查受理快照或历史旧快照是否覆盖更新版本。

### 面试追问

- 查询接口 500，为什么不能把任务改成 FAILED？
- 一个全局 loading 能否描述多个上传和多个任务？
- 什么情况下停止轮询，什么情况下需要恢复？
- 页面刷新后，哪些数据来自 Java，哪些只是缓存？

### 本轮产物与完成标准

保留状态分类表和网络请求观察。每个任务状态独立，查询故障保留快照，终态停止跟踪，刷新从后端恢复，两个视图没有冲突状态。

## 11. 第8轮：关键测试与故障回归

### 学什么

- 单元测试、集成测试、手工验证分别能证明什么。
- Mock、真实 MySQL、可替换 Sleeper/Clock、可控阻塞和请求模拟的用途。
- 对行为写断言；测试通过能证明的范围与不能证明的范围。

### 怎么学与怎么做

1. 汇总前面各轮已写测试，按验收要求查漏，不机械追求用例数量。
2. Java重点检查步骤顺序、三阶段失败中断、受理异步、终态稳定与个人归属。
3. 前端重点检查多任务隔离、查询异常不改业务状态、终态停更、卸载/身份变化清理。
4. 亲手写一个关键断言，说明它会拦住哪种真实错误；临时引入该错误，看到测试失败后再修复。
5. 用真实 MySQL 验证初始化、Mapper 和关键状态写入，补足 Mock 无法证明的部分。

### 故障实验

让失败后继续执行下一步骤，或让查询错误改写任务状态，确认相应测试真正报错。使用可控时间和调度代替长时间等待，观察测试是否稳定。

### 面试追问

- 这些测试分别证明了什么？哪些效果还需要实际运行验证？
- 为什么只 Mock Mapper 不能证明 SQL 能在 MySQL 正常运行？
- 如何证明接口没有等待 Worker 完成，避免依赖脆弱的耗时阈值？

### 本轮产物与完成标准

保留“要求 → 测试 → 结果/限制”映射和一次失败再修复记录。自己能解释核心断言，并知道未覆盖的边界。

## 12. 第9轮：CI 与容器交付

### 学什么

- 源码、依赖、构建产物、镜像、容器和数据卷的区别。
- 宿主机地址、容器服务名、端口、环境变量与前端/服务端配置。
- 健康检查、启动依赖和数据库初始化。
- CI触发条件、检查阶段、失败定位和版本复现。

### 怎么学与怎么做

1. 完善 Dockerfile、Compose、非敏感示例配置与持久化卷。
2. 沿“浏览器 → Next.js → Java → MySQL”列出每一跳实际使用的地址，解释 localhost 在不同位置代表谁。
3. 配置 push/PR 的前端 lint、类型检查、测试/构建及 Java 测试/构建。
4. 亲手修改一个非敏感配置并验证生效范围，确认是否需要重建镜像。
5. 在明确的测试环境验证干净初始化和已有数据卷再次启动，记录具体命令与结果。

### 故障实验

设置错误服务地址、数据库暂不可用、缺少配置，观察失败阶段；停止再启动容器验证记录与文件保留。重置实验只使用明确的测试数据，操作前确认数据卷，避免误删正常成果。

### 面试追问

- 本地能运行，容器内为什么可能连不上数据库？
- 容器删除后，任务历史和上传文件是否还在？由什么决定？
- lint、类型检查、测试和构建分别在检查什么？
- 如何让别人从源码按文档复现，而不是依赖自己的环境？

### 本轮产物与完成标准

保留实际 Compose 启动与 CI 结果、配置说明、数据持久化观察。能定位一类配置错误，交付入口与 README 一致；未运行成功的环境明确标为未验证。
